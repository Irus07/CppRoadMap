# 01. Объектная модель, полиморфизм и таблица виртуальных функций (vtable)

> В C# каждый класс неявно наследуется от `System.Object`, содержит заголовок метода (`MethodTable`) и указатель синхронизации (`SyncBlock`). В C++ объект имеет **ровно тот размер, который занимают его поля**, если только в нём нет виртуальных функций.

---

## 1. Анатомия класса в памяти

Если класс не содержит виртуальных методов:
```cpp
class Point {
    int x; // 4 байта
    int y; // 4 байта
};
```
Размер `sizeof(Point)` равен ровно **8 байтам**. Никаких скрытых метаданных!

### Что происходит, когда появляется `virtual`?
```cpp
class Shape {
    int id; // 4 байта (+ 4 байта padding для выравнивания)
public:
    virtual void Draw() = 0; // Чисто виртуальный метод (абстрактный)
};
```
В начало объекта компилятор скрытно добавляет **указатель на таблицу виртуальных функций (`vptr`)** — 8 байт на 64-битной платформе.
Теперь `sizeof(Shape)` = 16 байт!

```
Память объекта Shape в куче/стеке:
[ vptr (8 байт) ] ----> [ Таблица vtable для данного класса ]
[ id   (4 байта) ]       - указатель на реализацию Draw()
[ pad  (4 байта) ]
```

---

## 2. Как работает динамический диспетчер (Dynamic Dispatch)

Когда вы вызываете виртуальный метод:
```cpp
Shape* s = GetShape();
s->Draw();
```
Процессор выполняет следующие шаги:
1. Загружает адрес `s`.
2. Разыменовывает скрытый указатель `s->vptr`.
3. Смещается в таблице `vtable` на индекс метода `Draw`.
4. Совершает косвенный переход по адресу функции (`call [rax+offset]`).

**Цена полиморфизма:**
* +8 байт на каждый объект с `vptr`.
* Небольшая потеря кэш-локальности (косвенный переход).
* Компилятору труднее заинлайнить виртуальный вызов (хотя работает оптимизация **Devirtualization**, если тип известен точно).

## 3. Ключевые слова: `override`, `final`, `= 0`

| C# аналог | C++ синтаксис | Назначение |
| :--- | :--- | :--- |
| `abstract void Work();` | `virtual void Work() = 0;` | Чисто виртуальный метод. Делает класс абстрактным. |
| `override void Work()` | `void Work() override;` | **Обязательно используйте!** Защищает от опечаток в сигнатуре. |
| `sealed class Foo` | `class Foo final` | Запрещает дальнейшее наследование. Помогает оптимизатору. |
| `sealed override void M()` | `void M() final override;` | Запрещает переопределение метода потомками. |

### Почему `override` критически важен?
```cpp
class Base {
public:
    virtual void Process(const std::string& text);
};

class Derived : public Base {
public:
    // Опечатка в типе аргумента (забыт const):
    void Process(std::string& text) override; 
    // С КЛЮЧЕВЫМ СЛОВОМ OVERRIDE КОМПИЛЯТОР ВЫДАСТ ОШИБКУ!
    // Без override компилятор счел бы это новой перегрузкой, и полиморфизм бы сломался.
};
```

## 4. Смертный грех C++: невиртуальный деструктор

В C# уничтожением управляет GC, поэтому проблемы удаления производных классов не существует.
В C++:

```cpp
class Animal {
public:
    // ПЛОХО:
    // ~Animal() = default; 

    // ОБЯЗАТЕЛЬНО:
    virtual ~Animal() = default; 
};

class Dog : public Animal {
    std::string breed; // Внутри живет динамический буфер
};

Animal* pet = new Dog();
delete pet; 
```

* **Если деструктор базового класса `virtual`:**
  Вызывается деструктор `Dog`, освобождает строку `breed`, затем вызывается деструктор `Animal`. Память цела.
* **Если деструктор НЕ `virtual`:**
  Вызывается **только** деструктор `Animal`. Деструктор `Dog` даже не узнает об удалении! Поля `Dog` останутся висеть в памяти. Это чистое Undefined Behavior.

> **Правило:** Базовый класс, рассчитанный на полиморфное использование, **всегда** обязан иметь `virtual ~Base() = default;`.
