# 01. Деструкторы в C++: Полное руководство для новичка

> **Главный парадокс:** В C# синтаксис `~MyClass()` обозначает финализатор, который почти никогда не используют. В C++ деструктор `~MyClass()` — это один из **самых важных инструментов языка**, лежащий в основе управления памятью, файлами, сетью и потоками.

---

## 1. Анатомия деструктора

Деструктор — это специальный метод класса, который вызывается автоматически, когда объект уничтожается.

```cpp
class Logger {
public:
    // Конструктор:
    Logger() {
        std::cout << "[+] Logger created\n";
    }

    // Деструктор (тильда ~ перед именем класса):
    ~Logger() {
        std::cout << "[-] Logger destroyed\n";
    }
};
```

### 3 строгих правила деструктора:
1. **Имя всегда совпадает с именем класса с тильдой `~` впереди.**
2. **У деструктора не может быть параметров** (его нельзя перегрузить — деструктор у класса всегда только один).
3. **Деструктор ничего не возвращает** (перед ним нельзя писать даже `void`).

---

## 2. Разница между C# и C++: Детерминированность

В C# уничтожением объектов заправляет Garbage Collector (сборщик мусора):
* Вы создали объект, он отработал, ссылка пропала.
* Когда освободится память? Никто не знает. Может через 5 секунд, может через 10 минут, когда GC решит провести сборку.
* Для ручной очистки в C# приходится реализовывать интерфейс `IDisposable` и писать блок `using (...)`.

### В C++ уничтожение ДЕТЕРМИНИРОВАНО (с точностью до наносекунды):
Как только поток выполнения программы доходит до закрывающей фигурной скобки `}` блока, в котором был создан объект, **в этот же такт процессора вызывается деструктор**.

```cpp
#include <iostream>

void DoWork() {
    std::cout << "Entering function\n";
    {
        Logger localLog; // 1. Вызывается конструктор Logger
        std::cout << "Inside local block\n";
    } // 2. СКОБКА ЗАКРЫЛАСЬ: ЗДЕСЬ ПРЯМО СЕЙЧАС вызывается ~Logger()!

    std::cout << "Exiting function\n";
}

int main() {
    DoWork();
    return 0;
}
```

Вывод программы:
```text
Entering function
[+] Logger created
Inside local block
[-] Logger destroyed
Exiting function
```

## 3. Точный список: Когда вызывается деструктор?

Деструктор объекта вызывается автоматически в следующих ситуациях:

1. **Локальный объект на стеке:** при выходе из области видимости `{ ... }` (окончание функции, тела цикла `for`, блока `if`).
2. **При аварийной ситуации (Раскрутка стека / Stack Unwinding):** если выброшено исключение (`throw`), C++ автоматически поднимется по стеку вызовов и аккуратно вызовет деструкторы **всех** созданных по пути объектов. Ресурсы не утекут даже при ошибках!
3. **Объект в куче:**
   * При явном вызове `delete ptr;` (если вы использовали сырой указатель).
   * Автоматически, когда завершается время жизни умного указателя `std::unique_ptr` или обнуляется счётчик `std::shared_ptr`.
4. **Поле внутри другого класса:** когда уничтожается внешний («родительский») объект, автоматически уничтожаются все его внутренние поля.
5. **Глобальные и статические переменные:** при полном завершении работы программы (после выхода из `main`).

## 4. Порядок уничтожения: Правило обратного порядка (LIFO)

В C++ действует фундаментальное строительное правило: **«Кто последним создан — тот первым уничтожается»** (как стопка тарелок):

### А. Локальные переменные на стеке:
```cpp
{
    Item a("First");
    Item b("Second");
    Item c("Third");
} 
// Порядок уничтожения:
// 1. Сначала уничтожится c ("Third")
// 2. Затем b ("Second")
// 3. Последним уничтожится a ("First")
```

### Б. Поля внутри класса:
Поля класса уничтожаются в порядке, **обратном их объявлению в классе**:
```cpp
class Player {
    Weapon weapon_; // Создается 1-м, уничтожается 2-м
    Armor armor_;   // Создается 2-м, уничтожается 1-м
};
```

### В. При наследовании (Снос здания сверху вниз):
Конструкторы работают снизу вверх (Фундамент ➔ Стены ➔ Крыша).
Деструкторы работают строго наоборот (Крыша ➔ Стены ➔ Фундамент):

```cpp
class Base {
public:
    Base() { std::cout << "1. Base constructed\n"; }
    virtual ~Base() { std::cout << "4. Base destroyed\n"; }
};

class Derived : public Base {
public:
    Derived() { std::cout << "2. Derived constructed\n"; }
    ~Derived() override { std::cout << "3. Derived destroyed\n"; }
};

int main() {
    Derived d;
}
```
Вывод:
```text
1. Base constructed
2. Derived constructed
3. Derived destroyed
4. Base destroyed
```
*Сначала разбирается производная часть (`Derived`), и только потом — базовая (`Base`).*

## 5. Смертный грех C++: Виртуальный деструктор

Если класс планируется использовать как полиморфную базу (передавать по указателю или ссылке на базовый класс), **деструктор базового класса ОБЯЗАН быть объявлен как `virtual`**:

```cpp
class Enemy {
public:
    // ОБЯЗАТЕЛЬНО:
    virtual ~Enemy() = default; 
};

class Boss : public Enemy {
private:
    int* heavyBuffer_ = new int[10000]; // Выделили память
public:
    ~Boss() override {
        delete[] heavyBuffer_; // Освобождаем память
        std::cout << "Boss memory cleaned up\n";
    }
};

int main() {
    Enemy* enemy = new Boss();

    // Если ~Enemy() НЕ виртуальный:
    // Вызовется ТОЛЬКО деструктор Enemy! 
    // Деструктор Boss() даже не запустится, heavyBuffer_ утечет навсегда!
    delete enemy; 
}
```

> **Золотое правило:** Добавили в класс хотя бы одну виртуальную функцию? Сразу пишите: `virtual ~ClassName() = default;`.

## 6. Деструктор НИКОГДА не должен выбрасывать исключения!

В современном C++ (начиная с C++11) все деструкторы по умолчанию имеют спецификатор **`noexcept`**.

**Почему?**
Представьте: функция выбросила исключение. Начинается раскрутка стека. В этот момент вызывается деструктор объекта, и внутри деструктора **тоже** выбрасывается исключение.
* В программе возникает ситуация: *два активных исключения одновременно*.
* Среда выполнения C++ не знает, какое из них обрабатывать, и немедленно вызывает функцию `std::terminate()` — **программа падает намертво без возможности перехвата**.

```cpp
class Database {
public:
    ~Database() {
        try {
            CloseConnection();
        } catch (const std::exception& e) {
            // ЛОГИРУЕМ ОШИБКУ, НО НИ В КОЕМ СЛУЧАЕ НЕ ВЫБРАСЫВАЕМ НАРУЖУ!
            std::cerr << "Failed to close DB: " << e.what() << "\n";
        }
    }
};
```

## 7. Когда вам РЕАЛЬНО нужно писать деструктор? (Rule of Zero)

Вам как новичку может показаться, что деструктор нужно писать в каждом классе. **Это не так!**

Существует «Правило нуля» (**Rule of Zero**):
> Если поля вашего класса состоят из стандартных типов (`std::string`, `std::vector`, `std::unique_ptr`, примитивов `int`/`double`), **не пишите деструктор вообще!**

Компилятор сгенерирует деструктор сам, и он идеально очистит все поля:
```cpp
// Идеальный класс: деструктор НЕ НУЖЕН!
class User {
private:
    std::string name_;           // Сама освободит свою строку
    std::vector<int> scores_;    // Сам освободит массив
    std::unique_ptr<Avatar> av_; // Сам сделает delete аватарки
};
```

### Деструктор нужен только если класс владеет «сырым» ресурсом операционной системы:
* Вы открыли файл через Сишный `fopen` ➔ в деструкторе нужен `fclose`.
* Вы открыли сетевой сокет через OS API ➔ в деструкторе нужен `closesocket`.
* Вы захватили низкоуровневый мьютекс WinAPI/pthread ➔ в деструкторе нужно освободить.
