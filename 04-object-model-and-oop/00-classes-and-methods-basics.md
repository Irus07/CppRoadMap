# 00. Основы ООП: Классы, структуры и методы (без зауми)

> Если вы пришли из C#, базовые концепции ООП вам уже знакомы: инкапсуляция, поля, методы, конструкторы. Но синтаксис C++ хранит несколько нюансов, которые поначалу ставят в тупик. Разберём всё просто и наглядно.

---

## 1. Как объявить класс и структуру

В C# вы объявляете модификатор доступа (`public`, `private`) перед **каждым** полем. 
В C++ модификаторы доступа задают **секции**:

```cpp
#include <iostream>
#include <string>

class Player {
private: // Все, что ниже, доступно только внутри класса:
    std::string name_;
    int health_ = 100; // Значение по умолчанию (Default Member Initializer)

public: // Все, что ниже, доступно отовсюду:
    // Конструктор
    Player(std::string name, int health) 
        : name_(std::move(name)), health_(health) {
    }

    // Обычный метод
    void TakeDamage(int damage) {
        health_ -= damage;
        if (health_ < 0) health_ = 0;
    }

    // Метод-геттер (помечен const, так как ничего не меняет)
    int GetHealth() const {
        return health_;
    }
}; // <-- ОБЯЗАТЕЛЬНАЯ ТОЧКА С ЗАПЯТОЙ В КОНЦЕ!
```

> ⚠️ **Главная ловушка новичка:** Точка с запятой `;` после закрывающей фигурной скобки класса **обязательна**. В C# её нет, а в C++ её отсутствие приведёт к странным ошибкам компилятора на следующей строчке.

## 2. Разница между `class` и `struct` в двух словах

В C# `struct` копируется по значению и живёт на стеке, а `class` — ссылка в куче.

В C++ **разница только в одной вещи**: что стоит по умолчанию, если вы не написали секцию `public:` или `private:`.

* В **`class`** всё по умолчанию **`private`**.
* В **`struct`** всё по умолчанию **`public`**.

```cpp
struct Point {
    int x = 0; // public по умолчанию
    int y = 0; // public по умолчанию
};

class Secret {
    int code = 1234; // private по умолчанию
};

int main() {
    Point p;
    p.x = 10; // ОК: в struct это public

    Secret s;
    // s.code = 0; // ОШИБКА КОМПИЛЯЦИИ: в class это private!
}
```

> **Правило из реальной жизни:** Используйте `struct` для простых наборов данных (координаты, цвет, конфиг), а `class` — когда есть логика, скрытые поля и методы защиты данных (инварианты).

## 3. Конструкторы и Список инициализации

В C# вы обычно присваиваете значения полям прямо в теле конструктора:
```csharp
// В C#
public Player(string name, int health) 
{
    this.name = name;
    this.health = health;
}
```

В C++ так делать **крайне не рекомендуется**! В C++ поля создаются **до** входа в фигурные скобки `{ }` конструктора. Если вы присвоите им значение внутри скобок, поле сначала проинициализируется значением по умолчанию, а затем перезапишется (двойная работа).

### Правильный способ: Список инициализации членов (Member Initializer List)

Список инициализации пишется через двоеточие `:` между сигнатурой конструктора и телом:

```cpp
class Player {
private:
    std::string name_;
    int health_;
    const int id_; // Константные поля МОЖНО инициализировать ТОЛЬКО так!

public:
    // Двоеточие начинает список инициализации:
    Player(std::string name, int health, int id)
        : name_(std::move(name)), // Инициализация поля name_
          health_(health),         // Инициализация поля health_
          id_(id)                  // Инициализация константы id_
    {
        // Тело конструктора пустое или содержит дополнительную валидацию:
        std::cout << "Player " << name_ << " created!\n";
    }

    // Конструктор по умолчанию (без параметров):
    Player() 
        : name_("Unknown"), health_(100), id_(0) {
    }
};
```

## 4. Конструктор по умолчанию: `= default`

Если вам нужен стандартный пустой конструктор, не пишите `{}` вручную. Поручите это компилятору через ключевое слово `= default`:

```cpp
class Weapon {
private:
    int damage_ = 10;
public:
    Weapon() = default; // Компилятор сам сделает оптимальный дефолтный конструктор
    Weapon(int dmg) : damage_(dmg) {}
};
```

## 5. Что такое `const` в конце метода?

Вы часто будете встречать в C++ коде странный синтаксис: `int GetValue() const;`.

* Слово `const` **после круглых скобок метода** означает: *«Этот метод гарантирует, что он НЕ изменяет никакие поля класса»*.
* В C# такого ключевого слова на методах долгое время не было (недавно появился `readonly` для методов структур).
* Если метод является геттером или просто что-то считает/печатает, **всегда** ставьте `const`.

```cpp
class HealthBar {
private:
    int current_ = 100;
public:
    // read-only метод:
    int GetCurrent() const { 
        // current_ = 50; // ОШИБКА: компилятор не даст изменить поле!
        return current_; 
    }

    // метод, меняющий состояние (без const):
    void Heal(int amount) {
        current_ += amount;
    }
};

void PrintInfo(const HealthBar& bar) {
    // Если бы GetCurrent() не имел пометки const, 
    // эту строчку было бы НЕВОЗМОЖНО скомпилировать для const-ссылки!
    std::cout << "HP: " << bar.GetCurrent() << "\n";
}
```

## 6. Указатель `this` (почему стрелочка `->`, а не точка `.`)

В C# вы обращаетесь к текущему экземпляру через `this.name`.

В C++ ключевое слово `this` является **указателем** на текущий объект. Поэтому для доступа к полям через него используется оператор стрелочки `->`:

```cpp
class Item {
private:
    int weight;
public:
    void SetWeight(int weight) {
        // this — это указатель (Item*), поэтому пишем ->
        this->weight = weight; 
    }
};
```
*(Впрочем, большинство C++ разработчиков предпочитают давать полям имена с подчёркиванием `weight_` или префиксом `m_weight`, чтобы не писать `this->`)*.
