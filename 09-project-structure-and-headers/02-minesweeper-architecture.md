# 02. Архитектура проекта: Игра «Сапёр» (Minesweeper)

> Разберём на практике, как спроектировать и разложить по файлам реальную игру «Сапёр» (Minesweeper) на C++, избегая спагетти-кода и ошибок линковки.

---

## 1. Декомпозиция системы: Из чего состоит Сапёр

Любую игру стоит делить на уровни ответственности:

```
[ main.cpp ]  (Точка входа, запуск консольного цикла)
      │
      ▼
 [ Game ]     (Управляет игровым процессом, победой/поражением, ходами игрока)
      │
      ▼
 [ Board ]    (Двумерное поле клеток, расстановка мин, подсчет соседей, алгоритм заливки Flood-Fill)
      │
      ▼
  [ Cell ]    (Состояние отдельной клетки: мина, открыта, флаг, число соседей)
```

---

## 2. Структура файлов проекта

Стандартная и самая чистая структура в индустрии:

```
minesweeper/
├── CMakeLists.txt           # Скрипт сборки всего проекта
├── include/                 # Папка для всех .hpp файлов (публичные интерфейсы)
│   ├── Cell.hpp             # Описание одной клетки
│   ├── Board.hpp            # Описание игрового поля
│   └── Game.hpp             # Описание логики игры
└── src/                     # Папка для всех .cpp файлов (реализация)
    ├── Cell.cpp
    ├── Board.cpp
    ├── Game.cpp
    └── main.cpp             # Точка входа
```

---

## 3. Разбор каждого компонента

### 1. Клетка (`Cell.hpp` / `Cell.cpp`)
Клетка — это простой тип. Ей не нужно знать ни про поле, ни про игру:
* **Свойства:** `has_mine`, `is_revealed`, `is_flagged`, `neighbor_mines`.
* **Методы:** геттеры и сеттеры флагов, отрисовка символа клетки (например: `#` — закрыта, `F` — флаг, `*` — мина, ` ` — пустая, `1..8` — цифра).

### 2. Игровое поле (`Board.hpp` / `Board.cpp`)
Поле владеет сеткой клеток.
* **Как хранить 2D поле в C++:**
  * Плохой способ: `Cell**` (ручные массивы указателей из C — медленно и опасно).
  * Способ проще: `std::vector<std::vector<Cell>>`.
  * **Профессиональный способ (Cache-Friendly):** Одномерный вектор `std::vector<Cell> cells_` размером `width * height`. 
    Доступ к клетке по координатам $(x, y)$:
    $$\text{index} = y \times \text{width} + x$$
* **Алгоритм Flood-Fill (Автооткрытие пустых зон):**
  Когда игрок открывает клетку с 0 мин вокруг, поле должно автоматически рекурсивно (или через очередь/BFS) открыть всех её соседей.

### 3. Игра (`Game.hpp` / `Game.cpp`)
Управляет состоянием:
* Хранит объект `Board board_`.
* Перечисление `enum class GameStatus { InProgress, Won, Lost };`.
* Обрабатывает команды: `OpenCell(x, y)` и `ToggleFlag(x, y)`.
* Проверяет условие победы: все клетки без мин открыты!

## 4. Почему именно такое разделение?

1. **Никаких циклических зависимостей:**
   * `Cell` ничего не знает про `Board`.
   * `Board` знает про `Cell` (`#include "Cell.hpp"`), но ничего не знает про `Game`.
   * `Game` знает про `Board` (`#include "Board.hpp"`).
   * Зависимости строго направлены в одну сторону!
2. **Легко сменить интерфейс:**
   Если вы захотите сделать не консольную версию, а графическую на **SFML** или **Raylib**, вам понадобится переписать только отрисовку! Классы `Cell`, `Board` и `Game` останутся **на 100% без изменений**.
