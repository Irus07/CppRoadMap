# 03. Пошаговый разбор кода Сапёра: От архитектуры к деталям

> В папке `examples/minesweeper/` находится полностью готовый и чистый проект «Сапёра». Давайте разберём ключевые инженерные приёмы, применённые в нём, чтобы вы поняли, почему код написан именно так.

---

## 1. Плоский массив `std::vector<Cell>` вместо 2D-массива

В C# или C часто пишут двумерные массивы:
```cpp
// ПЛОХО: Массив указателей на массивы (вектор векторов)
std::vector<std::vector<Cell>> grid; 
```
**Почему это плохо?** Внешний вектор хранит массив указателей. Каждый внутренний вектор выделяет отдельный кусок памяти в случайном месте кучи. Процессор при обходе такого поля постоянно ловит Cache Misses.

### Как сделано в нашем проекте (`Board.hpp` / `Board.cpp`):
Мы используем **одномерный вектор** размером `width * height`:
```cpp
std::vector<Cell> cells_;
```
Все клетки лежат в оперативной памяти **строго друг за другом в едином непрерывном блоке**.
Для доступа к клетке $(x, y)$ используется математическая формула:

$$\text{index} = y \times \text{width} + x$$

```cpp
int ToIndex(int x, int y) const noexcept {
    return y * width_ + x;
}
```

## 2. Гарантия безопасного первого клика

В классическом Windows «Сапёре» вы никогда не можете взорваться на первом же ходе.

### Как это реализовано в `Board::Initialize(firstX, firstY)`:
1. Поле изначально создаётся без мин.
2. При первом ходе игрока вызывается метод `Initialize(firstX, firstY)`:
   * Мы формируем список всех возможных координат поля, **исключая** координату `(firstX, firstY)`.
   * Перемешиваем координаты с помощью современного генератора случайных чисел `std::mt19937` (`std::shuffle`).
   * Первые `total_mines` координат из перемешанного списка получают мину `SetMine(true)`.
3. Только после этого мы пересчитываем количество соседей-мин (`CountNeighbors()`).

## 3. Алгоритм раскрытия пустых зон (Flood Fill)

Когда игрок открывает клетку, вокруг которой 0 мин (`neighbor_mines_ == 0`), игра должна автоматически открыть соседние клетки. Если среди соседей тоже есть пустые, процесс продолжается лавинообразно.

### Реализация через очередь (BFS / Волновой алгоритм):
Вместо рекурсии (которая на больших полях может вызвать переполнение стека — Stack Overflow), мы используем стандартную очередь `std::queue<std::pair<int, int>>`:

```cpp
void Board::FloodFillEmptyCells(int startX, int startY) {
    static constexpr int dx[] = { -1, -1, -1,  0, 0,  1, 1, 1 };
    static constexpr int dy[] = { -1,  0,  1, -1, 1, -1, 0, 1 };

    std::queue<std::pair<int, int>> q;
    q.push({ startX, startY });

    while (!q.empty()) {
        auto [cx, cy] = q.front(); // Структурное связывание (C++17)
        q.pop();

        for (int i = 0; i < 8; ++i) {
            int nx = cx + dx[i];
            int ny = cy + dy[i];

            if (IsValidCoordinate(nx, ny)) {
                Cell& neighbor = GetCell(nx, ny);
                if (!neighbor.IsRevealed() && !neighbor.IsFlagged() && !neighbor.HasMine()) {
                    neighbor.Reveal();
                    // Если у соседа тоже 0 мин, добавляем его в очередь для дальнейшего раскрытия:
                    if (neighbor.NeighborMines() == 0) {
                        q.push({ nx, ny });
                    }
                }
            }
        }
    }
}
```

## 4. Разделение игровой логики и ввода-вывода

Обратите внимание на распределение ответственности между классами:
* Класс `Board` **не знает про консоль** и ввод с клавиатуры (`std::cin`). Он лишь хранит поле и выполняет правила игры.
* Класс `Game` управляет статусом (`InProgress`, `Won`, `Lost`) и обрабатывает пользовательский ввод.
* Это позволяет в будущем без труда заменить консольный ввод `std::cin >> action` на клики мыши в графическом окне (SFML, SDL2 или Unreal Engine), не меняя ни единой строчки в `Board.cpp` или `Cell.cpp`.
