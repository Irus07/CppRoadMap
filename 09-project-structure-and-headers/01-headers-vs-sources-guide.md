# 01. Как делить проект на файлы: Заголовочные (.h/.hpp) и Исходные (.cpp)

> В C# каждый класс обычно лежит в одном файле `User.cs`, а компилятор `Roslyn` сам видит все типы в проекте. В C++ модель компиляции устроена совершенно иначе, и непонимание её принципов — причина 90% ошибок новичков.

---

## 1. Модель компиляции C++: Почему нельзя как в C#

Сборка C++ программы проходит в три строгих этапа:

```
[ Player.hpp ]           [ Player.hpp ]
      │ (копируется)           │ (копируется)
      ▼                        ▼
[ Player.cpp ]           [ main.cpp ]
      │ (компиляция)           │ (компиляция)
      ▼                        ▼
[ Player.obj ]           [ main.obj ]  <-- Translation Units (независимые бинарники)
      \                       /
       \                     /
        ▼                   ▼
           [ LINKER (Линковщик) ]
                    │
                    ▼
           [ Game.exe (Бинарник) ]
```

### Главные факты:
1. **Директива `#include` — это тупой копипаст:**
   Препроцессор берёт содержимое заголовочного файла и буквально вставляет его текст в то место, где написана строчка `#include`.
2. **Файлы `.cpp` компилируются независимо:**
   Когда компилятор собирает `main.cpp`, он **вообще ничего не знает** о существовании файла `Player.cpp`.
3. **Линковщик (Linker) склеивает всё вместе:**
   Линковщик ищет соответствия между вызовами функций в `main.obj` и их реальными телами в `Player.obj`.

## 2. Объявление (Declaration) vs Определение (Definition)

В этом разделении кроется весь смысл файлов `.hpp` и `.cpp`:

### Объявление (`Declaration`) — пишется в `.hpp`:
Говорит компилятору: *«Такой тип или функция существует, вот её имя и аргументы, поверь мне на слово»*.
```cpp
// Player.hpp
#pragma once
#include <string>

class Player {
private:
    std::string name_;
    int health_ = 100;

public:
    Player(std::string name); // Объявление конструктора
    void TakeDamage(int damage); // Объявление метода
    int GetHealth() const;       // Объявление метода
};
```

### Определение (`Definition`) — пишется в `.cpp`:
Реализует логику (тело функции в фигурных скобках `{ ... }`):
```cpp
// Player.cpp
#include "Player.hpp" // Обязательно подключаем свой заголовок!
#include <iostream>

Player::Player(std::string name) 
    : name_(std::move(name)) {
}

void Player::TakeDamage(int damage) {
    health_ -= damage;
    if (health_ < 0) health_ = 0;
}

int Player::GetHealth() const {
    return health_;
}
```

## 3. Защита от повторного включения: `#pragma once`

Представьте ситуацию:
* Файл `Cell.hpp` описывает клетку поля.
* Файл `Board.hpp` делает `#include "Cell.hpp"`.
* Файл `Game.hpp` делает `#include "Board.hpp"` и `#include "Cell.hpp"`.

В результате в `Game.cpp` текст файла `Cell.hpp` будет скопирован **дважды**! Компилятор выдаст ошибку: `error C2011: 'Cell': 'class' type redefinition`.

### Решение:
Всегда первой строчкой в **каждом** `.hpp` файле пишите:
```cpp
#pragma once
```
Это директива говорит компилятору: *«Если этот файл уже был включён в текущий `.cpp`, не включай его повторно»*.

*(Устаревший C-аналог: `#ifndef CELL_HPP #define CELL_HPP ... #endif`)*.

## 4. Смертельная ошибка новичка: `LNK2005 / Multiple Definition`

**Вопрос:** Почему нельзя просто писать весь код прямо в `.h` файле, как в C#?

**Ответ:** Если вы напишете тело обычной функции в `.hpp`:
```cpp
// MathUtils.hpp
#pragma once

int Add(int a, int b) { // ОШИБКА: тело функции прямо в заголовке!
    return a + b;
}
```
И подключите `MathUtils.hpp` в `Player.cpp` и в `main.cpp`:
1. В `Player.obj` скомпилируется машинный код функции `Add`.
2. В `main.obj` скомпилируется машинный код функции `Add`.
3. Линковщик попытается объединить их и упадёт с ошибкой:
   **`LNK2005: int Add(int, int) already defined in Player.obj`** (Нарушение правила одного определения — ODR).

### Исключения (что МОЖНО писать в `.hpp`):
1. **Шаблоны** (`template <typename T>`) — компилятору нужен весь исходный код для генерации типов.
2. Методы, написанные **прямо внутри объявления класса** (они автоматически считаются `inline`).
3. Функции, явно помеченные ключевым словом **`inline`** (`inline int Add(...)`).
4. Константы времени компиляции (`constexpr int MaxSize = 100;`).

## 5. Циклические зависимости и Опережающее объявление (Forward Declaration)

Классический тупик в C++:
* Класс `Player` должен знать про класс `Game`.
* Класс `Game` содержит вектор игроков `std::vector<Player>`.

Если в `Player.hpp` написать `#include "Game.hpp"`, а в `Game.hpp` написать `#include "Player.hpp"` — препроцессор войдёт в цикл, и компиляция сломается.

### Решение: Forward Declaration
Если вашему классу в заголовочном файле нужен только **указатель** или **ссылка** на другой класс, вам **НЕ НУЖНО** подключать его `.hpp` файл! Достаточно сказать, что такой класс существует:

```cpp
// Player.hpp
#pragma once

// Опережающее объявление (Forward Declaration):
class Game; // Мы просто говорим: "класс Game где-то существует"

class Player {
private:
    Game* game_ = nullptr; // ОК: для указателя компилятору достаточно знать, что Game - это класс (указатель всегда занимает 8 байт)

public:
    void SetGame(Game* g);
};
```

А вот в файле `Player.cpp`, где вы реально будете вызывать методы `game_->Update()`, вы делаете полноценный:
```cpp
// Player.cpp
#include "Player.hpp"
#include "Game.hpp" // Подключаем только здесь, в cpp!
```

| Когда ДОСТАТОЧНО `class Foo;` | Когда ОБЯЗАТЕЛЕН `#include "Foo.hpp"` |
| :--- | :--- |
| Поле является указателем: `Foo* ptr` | Поле хранится по значению: `Foo obj` (компилятору нужно знать размер `sizeof(Foo)`) |
| Поле является ссылкой: `Foo& ref` | Вы вызываете метод: `obj->DoSomething()` |
| Параметр метода: `void Bar(const Foo& f)` | Ваш класс наследуется: `class Bar : public Foo` |
