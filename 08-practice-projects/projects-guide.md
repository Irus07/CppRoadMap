# Практические проекты (Milestones) для закрепления

> Чтение документации даёт знание, но инстинкты C++ вырабатываются только на практике. Ниже подобраны 4 проекта, каждый из которых бьёт точно в ключевые механизмы языка.

---

## 🎯 Milestone 1: Свой контейнер `MyVector<T>`

* **Цель:** Полностью понять, как вектор управляет сырой памятью и почему Rule of 5 критично.
* **Что нужно реализовать:**
  1. Внутренний буфер памяти через `std::allocator<T>` или вызовы оператора `::operator new(sizeof(T) * cap)`.
  2. Конструктор, деструктор (уничтожение только живых элементов через `std::destroy_at`).
  3. Конструктор копирования (глубокое копирование) и оператор присваивания.
  4. Конструктор перемещения (`noexcept`) и перемещающее присваивание.
  5. Методы `push_back(const T&)`, `push_back(T&&)` и `emplace_back(Args&&... args)` (изучение Perfect Forwarding и `std::forward`).
  6. Базовые итераторы (`begin()`, `end()`), чтобы работал цикл `for (auto x : myVec)`.
* **Тест на прочность:** Прогнать ваш `MyVector` через AddressSanitizer на векторе строк `std::string` и проверить отсутствие утечек памяти.

## 🎯 Milestone 2: Zero-Allocation Парсер логов

* **Цель:** Научиться обрабатывать гигабайты текстовых данных без единого выделения памяти в куче.
* **Что нужно реализовать:**
  1. Отображение файла логов веб-сервера (Nginx / Apache) в память через Memory-Mapped Files (библиотека `mio` или WinAPI `CreateFileMapping`).
  2. Разбор строк лога (IP-адрес, Timestamp, HTTP-метод, URL, статус-код) с использованием `std::string_view`.
  3. Построение аналитического отчёта (топ-10 посещаемых URL, количество ошибок 4xx/5xx) с помощью **C++20 Ranges**:
     ```cpp
     auto topUrls = logs 
         | std::views::filter([](const auto& log) { return log.status >= 400; })
         | std::views::transform(&LogEntry::url)
         // ...
     ```
* **Сравнение с C#:** Сравните потребление оперативной памяти и скорость работы вашего C++ парсера со стандартным `File.ReadAllLines()` на C#.

## 🎯 Milestone 3: Потокобезопасный Thread Pool

* **Цель:** Освоить современную синхронизацию, атомики и шаблоны задач.
* **Что нужно реализовать:**
  1. Пул воркеров на базе `std::jthread` (размером с `std::thread::hardware_concurrency()`).
  2. Потокобезопасная очередь задач (`std::queue<std::move_only_function<void()>>` или лямбды).
  3. Синхронизация очереди через `std::mutex` и `std::condition_variable`.
  4. Метод отправки задачи `Submit(Func f, Args... args)`, который возвращает `std::future<ReturnType>` для ожидания результата вызывающим кодом.
  5. Корректное завершение работы пула с остановкой потоков по `stop_token`.

## 🎯 Milestone 4: Сетевой Key-Value сервер (Mini-Redis)

* **Цель:** Полноценный законченный проект системного уровня.
* **Что нужно реализовать:**
  1. Асинхронный сервер на `asio` или сокетах OS.
  2. Поддержка базовых команд по текстовому протоколу: `SET key val`, `GET key`, `DEL key`, `EXPIRE key ttl`.
  3. Хранилище на базе `std::unordered_map` с поддержкой LRU-кэша (Least Recently Used) для ограничения размера памяти.
  4. Потокобезопасный доступ к данным с разделяемой блокировкой (Shared Mutex — Read-Write Lock).
  5. Оформление через CMake с поддержкой модульных тестов на фреймворке Catch2 или GoogleTest.
