# 01. Память без сборщика мусора и концепция RAII

> **Ключевая мысль:** В C++ нет сборщика мусора (GC). Освобождение памяти и закрытие ресурсов происходят не «когда-нибудь потом в фоне», а **детерминированно — в ту же наносекунду, когда объект выходит из зоны видимости (`scope`)**.

---

## 1. Стек vs Куча: Разница с C#

В C# вы привыкли к чёткому разделению:
* **Value Types (`struct`)** → живут на стеке (если не упакованы или не являются полями класса).
* **Reference Types (`class`)** → всегда создаются в куче через `new`, управляются сборщиком мусора (Garbage Collector).

### Как устроено в C++:
В C++ **любой тип** (и примитив, и структура, и сложный класс) может быть создан **как на стеке, так и в куче**.

```cpp
// 1. Создание на СТЕКЕ (быстро, автоматически очищается):
MyClass obj;            // Объект живет на стеке
std::vector<int> v;     // Сам объект вектора живет на стеке, но его буфер внутри — в куче

// 2. Создание в КУЧЕ (требует управления временем жизни):
auto p = std::make_unique<MyClass>(); // Умный указатель управляет объектом в куче
```

### Сравнение моделей памяти

| Характеристика | C# (.NET Runtime) | C++ (Native Memory) |
| :--- | :--- | :--- |
| **Куча (Heap)** | Управляемая куча (GC Heap) + Large Object Heap | Нативная куча OS (`malloc` / `operator new`) |
| **Очистка кучи** | Недетерминированная (GC запускается по необходимости, ставит потоки на паузу — Stop-the-World) | **Детерминированная**: память освобождается ровно в момент вызова деструктора |
| **Утечки памяти** | Возможны из-за «висячих» ссылок (события, статические коллекции) | Возможны, если забыть освободить сырой указатель (в Modern C++ предотвращаются RAII) |
| **Фрагментация** | GC выполняет дефрагментацию (уплотнение кучи) | Дефрагментации нет (аллокаторы вроде mimalloc/jemalloc снижают фрагментацию) |

## 2. Что такое RAII (Resource Acquisition Is Initialization)

**RAII** — это сердце C++. Паттерн означает:
1. **Захват ресурса происходит в конструкторе** (выделение памяти, открытие файла, захват сокета или мьютекса).
2. **Освобождение ресурса происходит в деструкторе** (`~ClassName()`).

Поскольку C++ гарантирует, что деструктор объекта на стеке **всегда вызывается при выходе из области видимости `{ ... }`** (даже если выброшено исключение), ресурсы никогда не утекают.

### Аналогия с C#: `using` и `IDisposable`
В C# для ресурсов вы пишете:

```csharp
// C#
using (var file = File.OpenRead("log.txt"))
{
    // работа с файлом
} // здесь неявно вызывается file.Dispose()
```

В C++ **любой объект ведёт себя так автоматически**! Не нужно писать ключевое слово `using`:

```cpp
// C++
{
    std::ifstream file("log.txt"); // Файл открыт в конструкторе
    // работа с файлом
} // СКОБКА ЗАКРЫЛАСЬ: деструктор std::ifstream автоматически закрывает дескриптор файла!
```

## 3. Деструктор vs Finalizer (`~MyClass`)

В C# синтаксис `~MyClass()` обозначает **финализатор**. Вы знаете, что в C# писать финализаторы крайне не рекомендуется, потому что они замедляют GC и вызываются непредсказуемо.

В C++ `~MyClass()` — это **детерминированный деструктор**:
* Он вызывается **сразу**, когда управление покидает блок.
* Никаких очередей финализации, никакой паузы GC.
* В деструкторе можно и нужно освобождать любые ресурсы.

```cpp
#include <iostream>

class ScopedTimer {
public:
    ScopedTimer() { std::cout << "Timer started\n"; }
    ~ScopedTimer() { std::cout << "Timer stopped!\n"; }
};

void Test() {
    ScopedTimer timer; // Конструктор
    std::cout << "Working...\n";
} // Конец функции: деструктор timer вызывается ЗДЕСЬ гарантированно!

int main() {
    Test();
    return 0;
}
```

Вывод:
```text
Timer started
Working...
Timer stopped!
```

## 4. Главные выводы для разработчика с C#
1. **Не используйте `new` там, где можно создать объект на стеке.** Стек в десятки раз быстрее кучи и освобождается бесплатно сдвигом указателя регистра `rsp`.
2. Оборачивайте любые ресурсы (файлы, мьютексы, сокеты, OpenGL-текстуры) в RAII-обертки (классы с деструктором).
3. В стандартной библиотеке C++ уже есть готовые RAII-типы: `std::unique_ptr`, `std::vector`, `std::string`, `std::lock_guard`, `std::fstream`.
