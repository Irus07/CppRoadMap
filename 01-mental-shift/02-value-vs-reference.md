# 02. Семантика значений (Value Semantics) vs Семантика ссылок

> **Ключевая мысль:** В C# при передаче объекта класса вы передаёте ссылку на объект в куче. В C++ всё по умолчанию передаётся и присваивается **по значению (копируется)**, пока вы явно не укажете ссылку (`&`) или указатель (`*`).

---

## 1. Сравнение поведения при присваивании

### В C#:
```csharp
class Person { public string Name; }

var p1 = new Person { Name = "Alice" };
var p2 = p1; // Копируется ССЫЛКА! Оба указывают на один объект
p2.Name = "Bob";

Console.WriteLine(p1.Name); // Выведет "Bob"
```

### В C++ (по умолчанию):
```cpp
#include <iostream>
#include <string>

struct Person { std::string name; };

Person p1{ "Alice" };
Person p2 = p1; // Копируется ВЕСЬ ОБЪЕКТ целиком!
p2.name = "Bob";

std::cout << p1.name << "\n"; // Выведет "Alice" (p1 не изменился!)
```

В C++ для получения поведения, похожего на C#, нужно явно использовать ссылку или указатель.

---

## 2. Три способа обращения к переменной в C++

Представьте объект типа `std::string`:

### 1. По значению (Value)
```cpp
void Process(std::string s); // Создастся полная независимая копия строки!
```
* **Плюсы:** Безопасно, функция владеет своей копией, невозможно случайно повредить оригинал.
* **Минусы:** Дорого по производительности, если объект тяжёлый (выделение памяти в куче).

### 2. По ссылке (Reference — `&`)
```cpp
void Process(std::string& s); // Псевдоним оригинального объекта
```
* Аналог `ref` в C#.
* Функция может модифицировать оригинальный объект.
* Копирования не происходит (передаётся лишь адрес под капотом).

### 3. По константной ссылке (Const Reference — `const &`)
```cpp
void Process(const std::string& s); // Read-only доступ к оригиналу
```
* Аналог `in` в C#.
* **Золотой стандарт Modern C++** для передачи любых сложных параметров (строк, векторов, структур).
* Нулевые затраты на копирование + гарантия компилятора, что функция не изменит аргумент.

## 3. Ссылки (`&`) против Указателей (`*`)

Вы знаете указатели из языка C (`int* ptr`). Зачем в C++ появились ссылки (`int& ref`)?

| Свойство | Указатель (`int* ptr`) | Ссылка (`int& ref`) |
| :--- | :--- | :--- |
| **Синтаксис доступа** | Разыменование: `*ptr` или `ptr->field` | Обычный: `ref` или `ref.field` |
| **Может ли быть пустым (null)?** | Да (`nullptr`) | **Нет** (ссылка всегда обязана указывать на существующий объект) |
| **Можно ли перепривязать к другому объекту?** | Да (`ptr = &other;`) | **Нет** (инициализируется один раз при создании навсегда) |
| **Необходима инициализация?** | Нет (может быть мусором, если не инициализировать) | **Да** (нельзя создать неинициализированную ссылку) |

### Пример в коде:
```cpp
int x = 10;
int y = 20;

// Указатель:
int* p = &x;
p = &y; // Теперь p указывает на y
*p = 30; // y стал равен 30

// Ссылка:
int& r = x;
r = y; // ВНИМАНИЕ: это НЕ перепривязка к y! Это запись значения y в x! Теперь x == 20
```

## 4. Как правильно передавать аргументы в функции?

Сводная таблица лучших практик:

| Тип данных | Как передавать | Пример |
| :--- | :--- | :--- |
| Примитивы (`int`, `float`, `bool`, `enum`, указатели) | **По значению** | `void Calc(int a, double b)` |
| Тяжёлые объекты (только для чтения) | **По `const &`** | `void Draw(const Mesh& mesh)` |
| Строки для чтения (C++17+) | **`std::string_view`** | `void Print(std::string_view text)` |
| Объекты, которые функция должна изменить | **По `&`** | `void Update(State& state)` |
| Аргументы, которые функция должна забрать себе (sink) | **По значению + `std::move`** | `void SetName(std::string name)` |

## 5. Опасность висячих ссылок (Dangling Reference)

В C# сборщик мусора не позволит объекту исчезнуть, пока на него есть живая ссылка. 
В C++ **вы сами отвечаете за время жизни**:

```cpp
// КАТАСТРОФИЧЕСКАЯ ОШИБКА: Возврат ссылки на локальную переменную
const std::string& GetBadString() {
    std::string temp = "Dangerous";
    return temp; 
} // temp уничтожается здесь!

int main() {
    const std::string& ref = GetBadString();
    // ref указывает на память уничтоженного объекта!
    // Чтение ref — это Undefined Behavior (UB), программа может упасть или выдать мусор.
}
```

> **Правило:** Никогда не возвращайте `&` или указатель на локальную переменную, созданную на стеке внутри функции. Возвращайте по значению (компилятор C++ применит **RVO / Return Value Optimization**, и копирования не будет).
