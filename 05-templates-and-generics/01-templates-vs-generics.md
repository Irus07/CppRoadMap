# 01. Шаблоны C++ vs Дженерики C#

> На первый взгляд синтаксис `<T>` выглядит одинаково. Но под капотом **C++ Templates** и **C# Generics** — это две абсолютно разные вселенные.

---

## 1. Фундаментальная разница

| Характеристика | C# Generics | C++ Templates |
| :--- | :--- | :--- |
| **Когда компилируется?** | В байткод IL один раз; JIT генерирует машинный код при первом вызове типа | Полностью во время компиляции C++ (**Monomorphization**) |
| **Проверка типов** | Строгая проверка по ограничениям (`where T : ...`). Нельзя вызвать метод, если он не объявлен в ограничении | Неявная «утиная типизация» (Duck Typing): если код компилируется для типа `T`, значит тип подходит |
| **Кодогенерация** | Один вариант кода для всех `class` (работа через ссылки) + отдельные специализации для `struct` | Для **каждого** типа `T` генерируется отдельная копия ассемблерного кода |
| **Параметры** | Только типы (`T`) | Типы (`typename T`), значения констант (`size_t N`), шаблоны шаблонов |
| **Скорость выполнения**| Может иметь косвенные вызовы | Максимально возможная: полная оптимизация и инлайнинг под конкретный тип |

---

## 2. ШОК для C# разработчика: Почему шаблоны пишут в `.hpp` (заголовочных файлах)?

В C# каждый класс спокойно лежит в своём `.cs` файле и компилируется независимо.

В C++ файлы `.cpp` компилируются **по отдельности** (Translation Units).
* Если вы объявите шаблон в `.h`, а тело напишете в `.cpp`:
  Компилятор, собирая другой `.cpp` файл, **не увидит реализацию шаблона** и не сможет сгенерировать машинный код для `MyClass<int>`.
* При линковке вы получите знаменитую ошибку: `undefined reference to MyClass<int>::DoWork()`.

> **Правило:** Шаблоны функций и шаблонные классы всегда должны быть **полностью реализованы прямо в заголовочных файлах (`.h` / `.hpp`)**.

## 3. Нетиповые параметры шаблонов (Non-Type Template Parameters — NTTP)

В C++ параметром шаблона может быть не только тип, но и **константа времени компиляции** (число, размер, указатель, а с C++20 даже строка или плавающая точка!):

```cpp
template <typename T, size_t Size>
class FixedArray {
    T data_[Size]; // Память на стеке фиксированного размера!
public:
    size_t GetSize() const { return Size; }
};

int main() {
    FixedArray<int, 10> smallArray;  // Размер 10
    FixedArray<int, 100> largeArray; // Размер 100
    // Это ДВА РАЗНЫХ типа данных на этапе компиляции!
}
```
В C# такое невозможно — размер массива всегда передаётся аргументом в рантайме.

## 4. Специализация шаблонов (Template Specialization)

Вы можете написать общую логику для всех типов, но для конкретного типа (например, `bool` или `char*`) предоставить оптимизированную реализацию:

```cpp
#include <iostream>

// Общий шаблон:
template <typename T>
struct Formatter {
    static void Print(const T& val) {
        std::cout << "General value: " << val << "\n";
    }
};

// Полная специализация для bool:
template <>
struct Formatter<bool> {
    static void Print(const bool& val) {
        std::cout << "Boolean: " << (val ? "TRUE" : "FALSE") << "\n";
    }
};

int main() {
    Formatter<int>::Print(42);     // General value: 42
    Formatter<bool>::Print(true);  // Boolean: TRUE
}
```
Благодаря этой технике `std::vector<bool>` в C++ упаковывает булевы значения по 1 биту на флаг вместо 1 байта (экономия памяти в 8 раз).
